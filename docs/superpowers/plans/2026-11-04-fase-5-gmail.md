# Fase 5: Gmail, plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Conectar caixas Gmail ao Oxyn CRM, vincular e-mails aos cards automaticamente ou à mão, e enviar e responder pelo CRM.

**Architecture:**
- Um cliente REST do Gmail (`src/lib/gmail/`) chamado por route handlers do Next: OAuth em `/api/google/*` e sincronização no cron da Vercel em `/api/cron/gmail`.
- Tabelas `email_*` com RLS que herda a permissão do card.
- A interface é a aba E-mail dos cards, o módulo `/[empresa]/email`, a seção E-mail do perfil e os modelos em Configurações.

**Tech Stack:** Next.js 16 (App Router, server actions), Supabase (Postgres, RLS, pgTAP), vitest, Tailwind e shadcn, `node:crypto`.

**Spec:** `docs/superpowers/specs/2026-11-04-fase-5-gmail-design.md`

## Global Constraints

- **Português:** todo texto de interface, comentário e mensagem de commit em português do Brasil, no estilo do código vizinho.
- **Next.js 16:** antes de usar uma API do Next, ler o guia em `node_modules/next/dist/docs/`, porque esta versão mudou convenções (AGENTS.md).
- **Banco:**
  - Migrations em `supabase/migrations/` com prefixo `20261104…`.
  - O banco de dev é o de produção: só migrations aditivas. Nunca `reset`, `drop` de tabela existente ou `delete` em dados reais.
  - Aplicar com `pnpm db:migrate`.
- **Comandos:** `PATH=$HOME/.local/node/bin:$PATH` antes de `pnpm`. Testes: `pnpm test`, `pnpm test:db`, `pnpm typecheck`, `pnpm lint`.
- **Segredos:**
  - Nunca imprimir nem commitar `.env.local` ou tokens.
  - Variáveis novas: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GMAIL_TOKEN_KEY`.
  - Sem elas, a interface mostra "Integração com o Gmail ainda não configurada" e o cron devolve `{ skipped: "not_configured" }`.
- **Dependências:** nenhuma nova.
- **Escopos OAuth** (exatos): `openid email https://www.googleapis.com/auth/gmail.readonly https://www.googleapis.com/auth/gmail.send`.
- **Primeira carga:** 12 meses, `q = after:<YYYY/MM/DD> -in:chats -in:spam -in:trash`.
- **Domínios genéricos** (nunca casam): gmail.com, googlemail.com, hotmail.com, outlook.com, live.com, yahoo.com, yahoo.com.br, icloud.com, me.com, uol.com.br, bol.com.br, terra.com.br, ig.com.br, msn.com, protonmail.com.
- **Commits** terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Sem push.

## Review Focus

1. **Mensagem sem `text/html`:** só `text/plain`, ou multipart aninhado com `related` dentro de `alternative`. O corpo deve vir mesmo assim.
2. **Endereços:** cabeçalhos `"Nome, Sobrenome" <a@b.com>` (vírgula entre aspas) e maiúsculas devem casar com o contato.
3. **Sincronizar duas vezes** a mesma mensagem não duplica a conversa, a mensagem nem o vínculo. Vínculo desfeito à mão não volta.
4. **Visibilidade:** caixa privada não aparece para outro usuário mesmo com o card visível. Usuário sem acesso ao card não vê a conversa compartilhada.
5. **`invalid_grant` na renovação** marca a conta como `reconnect` sem derrubar as outras contas da execução.

### Task 2: Núcleo puro do Gmail

**Files (todos em `src/lib/gmail/`, com testes `*.test.ts` ao lado):**
- `crypto.ts`: `encryptToken(plain: string, keyB64: string): string` e `decryptToken(enc: string, keyB64: string): string`. Usa AES-256-GCM, com o formato `v1.<iv>.<tag>.<data>` em base64url. Chave com tamanho errado lança erro.
- `addresses.ts`:
  - `parseAddressList(header: string): { email: string; name: string | null }[]`: e-mail em minúsculo, respeitando vírgula entre aspas;
  - `domainOf(email: string): string`;
  - `GENERIC_DOMAINS`.
- `parse.ts`: `parseGmailMessage(msg: GmailMessage): ParsedMessage` (`gmailId`, `threadId`, `rfcMessageId`, `subject`, `from`, `to`, `cc`, `sentAt` ISO, `snippet`, `html | null`, `text | null`, `attachments[]`, `historyId`).
  - Decodifica base64url em UTF-8 e percorre as partes recursivamente.
  - Sem HTML, usa o texto. O HTML acima de 512 KB vira `null` (o texto fica).
  - Exporta também o tipo `GmailMessage`, no formato da API.
- `matcher.ts`:
  - `type ContactIndex = { personsByEmail: Map<string, { id; organizationId }[]>; orgsByDomain: Map<string, string[]>; openLeads: { id; personId; organizationId }[]; openDeals: { id; personId; organizationId }[] }`;
  - `matchMessage(addresses: string[], ownEmail: string, index: ContactIndex): { entity: "persons" | "organizations" | "leads" | "deals"; recordId: string }[]` sem duplicatas, com as regras da seção "Casador" da spec.
- `mime.ts`: `buildMime({ from, to, cc, subject, text, html, inReplyTo?, references? }): string` (CRLF, `MIME-Version`, `multipart/alternative`, assunto RFC 2047 `=?UTF-8?B?…?=` quando não-ASCII) e `toBase64Url(s: string): string`.
- `template.ts`: `renderTemplate(tpl: string, vars: Record<string, string | undefined>): string`. Troca `{{chave}}` (espaços tolerados) e deixa vazio o que falta.
- `oauth.ts`:
  - `GMAIL_SCOPES`;
  - `buildAuthUrl({ clientId, redirectUri, state }): string`;
  - `newState(): string` (32 bytes base64url);
  - `gmailConfig(): { clientId; clientSecret; tokenKey } | null` (lê o env; `null` se faltar algo).

- [ ] Testes primeiro (cobrir a Review Focus 1 e 2), implementar, `pnpm test src/lib/gmail` passa.
